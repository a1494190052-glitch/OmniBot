OmniBot 三天核心功能进展

Online、Offline 和交互链路都往前走了一步。

简单说：Online VLM 负责实时决策，Offline Function 负责沉淀能力，中间的交互链路负责召回、执行和留证。

时间范围 2026-06-03 至 2026-06-05
核心链路 Online -> Offline -> 交互闭环
主要对象 VLM / Function / RunLog / OmniFlow

总体结论

这三天的核心不是单点功能堆叠，而是把 Online VLM 和 Offline Function 接起来。

Online 侧能更好地理解当前任务并调用工具；Offline 侧能沉淀可复用 Function；交互侧把召回、执行、结果记录串成闭环。

Online：VLM 执行升级

核心变化

从单步动作，到可调用 Function

Online VLM 不只输出点击、输入、滑动，也可以看到本地 Function 候选，并选择调用已保存的 Function。

统一输出 Schema

工具调用格式收敛

统一 VLM action schema 和动态 function tools，同时补了文本 tool call fallback，降低 online 模型输出格式波动的影响。

Offline：能力沉淀升级

Function

学习结果继续沉淀为 Function

手动录制动作增量保存，并过滤 overlay 包名，让离线沉淀出来的 Function 来源更干净。

OmniFlow

流程结构开始收敛

引入 typed OmniFlow IR，并收敛 update pipeline，为后续 Function 编辑、回放和修复打基础。

交互：Online 和 Offline 接起来

召回

Offline Function 进入 Online VLM 默认上下文。 VLM 执行任务时可以看到本地已有能力。

执行

call_tool / call_function 统一。 单步工具和 Function 调用走更一致的执行路径。

留证

Function 调用结果写回 RunLog。 Online 执行过什么、结果是什么，可以在运行历史里看。

调试

新增 get_state 和可取消 VLM 任务。 当前状态能抓取，长任务也能中止。

三天对应关系

周三

Online

统一 VLM action schema，接入 Function tools，补 tool call fallback。

周四

Offline

录制增量保存，过滤 overlay 包，优化 Function recall 缓存门禁。

周五

交互
