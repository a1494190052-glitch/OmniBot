OmniBot 三天核心功能进展

这三天集中把“会录、会存、会召回、会执行”做得更闭环。

口径只看功能和使用效果：这三天有几项从 0 到 1 的能力进入链路，包括 MCP 抓状态、VLM 调 Function、Function 结果进 RunLog、可取消 VLM 任务和 typed OmniFlow IR。

时间范围 2026-06-03 至 2026-06-05
核心链路 学习录制 -> RunLog -> Function -> 召回执行
主要对象 OOB / OmniFlow / VLM / 手动录制

一句话结论

这三天不只是优化体验，而是把几块原来缺失的能力补进了闭环：抓状态、调 Function、记结果、可取消、结构化表达。

本轮最核心的变化是：Function 从“已有流程资产”变成 Agent/VLM 可以在任务里直接使用的工具；执行结果不再只停留在内部返回，而是进入 RunLog；OmniFlow 也开始从松散 Map 管线切到 typed IR。

01 用户操作

用户在真实 App 里点击、输入、滑动，系统记录操作轨迹。

02 RunLog 留证

每一步动作、页面状态和函数执行结果进入运行历史。

03 沉淀 Function

可复用流程被保存为 Function，而不是一次性命令。

04 Agent/VLM 召回

执行新任务时，模型能看到本地已有 Function 候选。

05 回放与修复

失败时保留上下文，后续可以定位、更新和继续优化。

从 0 到 1 的核心功能

MCP 状态抓取

新增 get_state：外部 Agent 可以抓当前屏幕状态

这不是单纯优化。之前外部工具链缺少统一的当前页面状态入口，这次新增 MCP get_state capture tool，让调试、回放和外部 Agent 能拿到当前屏幕上下文。

VLM 调 Function

VLM 任务里可以把本地 Function 当工具用

Function 召回进入 Agent/VLM 默认上下文，并统一动态 function tools。使用上从“VLM 只输出点击/输入/滑动”推进到“VLM 可以选择运行已保存 Function”。

RunLog 结果

Function 执行结果开始进入运行历史

VLM function 调用结果写入 RunLog。用户和开发者不只知道任务结束了，还能在时间线里看到 function 是否执行、返回了什么、失败在哪里。

任务控制

新增可取消的 OOB VLM 任务入口

新增 debug receiver 和脚本能力，长时间运行的 OOB VLM 任务可以从命令侧取消。以前这类任务更偏一次性启动，现在有了明确的停止控制。

OmniFlow

新增 typed OmniFlow IR

引入 typed step representation 替代松散 Map pipeline。它是后续 Function 编辑、回放、参数绑定和自动修复的结构化基础。

Function 一等入口

功能库替代命令库口径

UI 和工具口径从 command 收敛到 Function，功能库、Function 卡片和执行结果页统一表达“可复用能力”，不是临时命令列表。

稳定性和使用体验改进

学习模式

手动录制减少漏记和误记

录制动作改成增量保存，并过滤悬浮层包名，减少录制中断丢数据、误把 overlay 当目标 App 的问题。当前还在补文本输入无触摸锚点时的记录能力。

执行回放

Function 执行链路收敛

统一 call_tool / call_function，抽出 GoTo 导航逻辑，并减少 ScreenMask 这类执行遮挡，让回放路径更直接，问题定位更明确。

从使用上看，用户会感受到什么

学习一次

学习结果进入 Function 体系。 录制过程不再只依赖最后一次完整落盘，异常中断时丢失风险更低。

执行任务

Agent/VLM 可以直接调用已有 Function。 已学习流程会进入默认候选，任务执行从单步操作扩展到可复用流程调用。

看执行历史

Function 调用结果进入 RunLog。 时间线里能看到函数执行、失败步骤和页面状态，复盘不再只靠猜。

修失败流程

OmniFlow 有了结构化 IR 基础。 后续自动修复、参数绑定和流程增强可以基于明确 step 类型推进。

本轮修掉或缓解的问题

Function 执行分发错误

修复 OOB function run dispatch，避免工具调用路径不一致导致执行失败。

VLM tool call 解析不稳

补了文本形式 tool call 的 fallback，降低模型输出格式波动带来的失败。

录制动作丢失

动作增量持久化后，录制中断、脚本停止时更不容易全部丢失。

overlay 污染录制目标

录制卡片忽略 overlay 包，避免学习结果指向悬浮层而不是目标 App。

召回缓存不够谨慎

优化 VLM function recall cache gate，减少拿到过期或不匹配 Function。

执行遮挡和跳转耦合

去掉部分 ScreenMask 干扰，并把 GoTo 导航拆出来，降低回放跑偏和遮挡影响。
