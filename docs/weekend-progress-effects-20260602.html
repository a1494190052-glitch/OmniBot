OmniBot 周末至今工作总结

我们这几天主要推进了学习模式和 Function 召回执行闭环。

以下只总结我们做了哪些工作，不展开代码实现细节，也不扩展成产品宣传口径。

时间：2026-05-30 至 2026-06-02 主题：学习模式 / RunLog / Function / Agent 召回 口径：只总结我们的工作

总体工作

我们把“人工操作学习、RunLog 记录、Function 沉淀、Agent 召回、Function 执行和失败诊断”串成了一条更完整的链路。周末到现在的工作重点不是新增单点按钮，而是让这条链路可以跑通、可以复用、可以测试、可以继续修。

核心工作结果：用户教一遍的操作，可以进入 RunLog 和 Function 体系；Agent 后续可以召回并执行这些 Function。

重点 1：学习模式

已推进

我们把人工学习入口接到了指令库。

指令库里可以发起“学习操作”，用户完成一段真实操作后，系统会生成 RunLog，并尝试保存为人工 Function。

已推进

我们增强了手动录制稳定性。

重点处理了连续点击、滑动、文本输入、键盘区域、缺 XML 或截图等场景，减少学习流程中卡住、漏记、无法保存的问题。

重点 2：Agent 召回 Function 执行测试

已推进

我们把 Function 召回接入 Agent/VLM 决策链路。

Agent 在执行任务前，可以拿到本地 Function 候选，不必每次都从零开始探索页面。

已推进

我们补了召回后执行的测试覆盖。

测试重点覆盖了候选召回、参数填充、Function 执行、失败返回、后续恢复这些路径。

其他功能性工作

RunLog 转 Function

我们继续完善了从执行历史或学习记录中提取可复用 Function 的流程。

Function 参数化

我们收敛了带参数 Function 的调用方式，让 Agent 可以按任务目标补齐参数再执行。

Function 执行统计

我们在指令库卡片上补充运行次数、成功次数、失败次数和上次执行结果。

失败诊断

我们让 Function 执行失败时保留失败步骤、错误原因和后续恢复信息。

Function 更新闭环

我们推进了用失败 RunLog 作为证据来修复或增强已有 Function 的链路。

弹窗/广告干扰处理

我们补强了 checker 相关能力，用来处理复用执行中可能出现的广告或遮挡弹窗。

MCP 工具口径

我们统一了 Function 相关工具的命名和参数口径，减少外部 Agent 调用歧义。

VLM Function 调用

我们让 VLM 工具链可以选择运行已保存 Function，而不只是输出点击、输入、滑动。

执行历史 UI

我们继续完善 RunLog 时间线、指令库、Function 详情和执行结果展示。

可以汇报的工作结论

学习模式

我们已经把人工学习从“记录操作”推进到“生成 RunLog 并沉淀 Function”。

Agent 复用

我们已经把本地 Function 召回接进 Agent/VLM 执行链路，并做了执行测试。

能力闭环

我们正在形成“学习/执行 -> RunLog -> Function -> 召回执行 -> 失败修复”的闭环。
